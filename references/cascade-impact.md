# Cascade-Impact Scan

Brief pointer hub for the cascade-change awareness semantic. Full mechanics live in the referenced files below; do not duplicate their detail here.

**When**: before editing any project file that has dependent artifacts — docs/README, headers and comments, tests, schemas/types, examples, CHANGELOG, config/templates.

## Core Rule

- The cascade-changing proposal travels along-way with the main changing proposal; it is never a silent or deferred add-on
- Every cascade point becomes its own clarification item: explicit discretion on change-or-not per point, presented in the main session
- Any diffs go in the main session per the current Clarification Protocol
- The user may temporarily waive this protocol; a waiver is explicit, scoped, and recorded, never inferred from silence
- Scan depth: lightweight for every project-file edit; deep for signature, API, schema, or behavior changes
